# Angular Zürich Design System

Read [the design brief](../../../.ui-craft/brief.md) for product priorities and
learned constraints, and [the token inventory](../../../.ui-craft/tokens.md) for
the existing visual foundations. Check the referenced CSS before changing tokens.

Use the project’s established typography, Zürich blue palette, semantic tokens,
and shared components. A request for a bolder treatment should strengthen hierarchy
within that system; introduce a different palette or font family only when the
user’s requested design calls for it.

Follow the repository’s Angular, Preline, and accessibility rules in
[AGENTS.md](../../../AGENTS.md). Record actual new design rationale in
[the decision log](../../../.ui-craft/decisions.md) and validated reusable
compositions in [patterns](../../../.ui-craft/patterns.md) when useful. Keep token
values in the CSS and token inventory instead of duplicating them in this skill.
